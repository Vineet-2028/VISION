# Controlled review of VISION alerts

Begin review only after the release record identifies the frozen software and
marks the technical review gate ready. Use a seated reviewer with prerecorded
footage first. Record the release, source, window and reviewer session IDs.
The developer who generated a packet cannot mark a human judgment on the
reviewer's behalf.

1. Watch the assigned window at normal speed before looking at overlays. Note
   the object, motion and path interaction you can actually see. Use
   **uncertain** when identity, visibility or movement cannot be established.
2. Replay the same timestamps with tracks, corridor and alerts visible. Check
   that a presented event belongs to the same object over consecutive frames.
   Record an omitted object or interruption separately from an incorrect name.
3. Compare an interruption with its source frame and delivery time. Judge
   whether its wording, timing and frequency helped. A generic alert can be
   appropriate. A correct object name can still be distracting or late.
4. Save the window ID, source time, chosen judgment, uncertainty and optional
   explanation. Record missing or unusable evidence explicitly. Preserve the
   original machine packet when exporting the review.
5. End the session if playback, timestamps or overlays lose synchronization.
   Recreate the technical issue before attributing a judgment to the engine.

Keep pending windows pending. Record text-sink delivery, device callbacks and
reports from participants as distinct observations. This review evaluates
perceived usefulness on the assigned footage. Any later physical study needs a
separate protocol, real hardware and consent.
